# 学びアイ — しくみと開発の記録

「流動する教科書」をテーマにした総合学習アプリの試作です。小学校から高校までの 343 科目（各学科に共通する教科のすべてと、高校の専門教科 13 教科のすべて）の授業と、
仕様書・追加の要望書①にある各モードを一通り動かせます。モードごとに別のウィンドウが開き、並べて使えます
（ウィンドウの位置と大きさは、モードごとに覚えます）。

| モード | できること |
| --- | --- |
| 教科書 | 授業を読む。未作成の授業は AI がその場で書く。文を選んで質問へ進める |
| チャット | 授業の内容を、先生や同級生（先生 1 人と、同級生 20 人）に質問する |
| ノート | 見開きに書く。手書き（筆圧つき）とタイピング（罫線に沿って入力、縦書き）、英語の 4 線、図形、表、座標平面、画像・動画・リンク、範囲選択、検索、PDF 出力 |
| ノートの評価 | 先生がノートを読み、理解力・応用力・発想力を採点する |
| テスト | AI が作った問題を解く。受けている間は、ほかのモードや過去のノートを開けない |
| 成績 | 週ごとの 5 つの観点（上の 3 つ + 記憶力・継続力）と、特訓で育つ 5 つの力を見る |
| ディベート | 論題について同級生と肯定側・否定側に分かれ、立論 → 反対尋問 → 反駁 → 最終弁論と進め、第三者のジャッジが判定する。途中で先生に相談できる |
| 英会話 | 言いたいことを書く（日本語は英訳される）→ 声に出して言う → 伝われば相手に送られ、英語と日本語訳で返事が来る（英語は読み上げ） |
| 語彙力特訓 | 言葉・意味・例文のウィンドウと、練習用ノート。言葉を 5 回と、自分で考えた例文を 2〜3 文書くと、AI がノートを読んで確かめる。日本語／英語 |
| 漢字特訓 | 漢字のウィンドウ、書き順アニメーションのウィンドウ、書きこむノートのウィンドウ。正しい書き順で 10 回書き、言葉と例文を書き写すと次へ |
| 教材づくり | 全 343 科目（小学校 37・中学校 22・高校 55・高校の専門教科 229）の単元表と授業の本文を、AI にまとめて作らせる |
| 設定 | 画面ごとの表示倍率（100%〜400%）と、ショートカットキーの割り当てを変える |

## 科目と教材づくり

科目の一覧と学習範囲は `resources/content/catalog.json` にあります。単元表と授業の本文は、次の順で用意されます。

1. 人が書いて同梱したもの（`resources/content/<科目>/`。いまは中 1 数学の単元表と授業 3 回分）
2. AI が作ったもの（利用者のデータ置き場の `curricula/` と `lessons/`）

AI に作らせる方法は 2 つあります。

- **その場で作る**: 教科書モードで、まだ無い単元表や授業を開いてボタンを押す
- **まとめて作る**: 「教材づくり」の画面で始める。科目の順（中学校 → 小学校 → 高校）に作りつづける

まとめて作る処理（`src/main/library.ts`）は、Claude から届く使用量を見て、5 時間あたりの使用量が設定した割合
（既定 80%。50%〜100% から選べ、100% にすると上限に達するまで作りつづけます）か、1 週間あたりの使用量が 90% に達すると休み、回復する時刻になると自動で再開します。
同時に作る数は 1〜30 から選べ（既定 2）、作っている途中で変えてもその場で効きます。数が多いと始めや休み明けに AI への呼び出しが集中するので、作りはじめを 0.5 秒ずつずらしています。
アプリを開いている間だけ動き、閉じても次に開いたときに続きから再開します。作成している間は、PC の自動スリープを止めます。
既定では、作った授業をもう一度 AI に点検させます（`src/main/ai/authoring.ts` に指示文があります）。

小学校の科目は、小学生向けと、中学生以上が学び直すための深掘り版の 2 種類の本文を持ちます（教科書モードで切り替え）。
ただし、小学校の生活・音楽・図画工作・家庭・体育・外国語活動・道徳は、小学生向けだけです（科目表で `"deep": false`）。

教科によって、書き方を変えています（`src/main/ai/authoring.ts` の `SUBJECT_GUIDES`）。

- **実技のある教科**（体育、図画工作・美術・工芸・書道、技術、家庭、生活）: アプリの中では実技ができないので、動きや手順のポイントと、安全上の注意を書きます。点検でも、危険な行い方をすすめていないかを見ます。
- **道徳**: 決まった答えを覚える教科ではないので、「お話 → 考えてみましょう → 考えるヒント」の形にし、一つの考えを正解として押しつけません。点数をつけるテストの対象からも外しています。
- 総合的な学習（探究）の時間と特別活動は、決まった内容を教える教科ではないので、科目にしていません。

高校の専門教科（主として専門学科で開設される教科）は、学習指導要領の 13 教科 229 科目がすべてあります
（農業 30・工業 59・商業 20・水産 22・家庭 21・看護 13・情報 12・福祉 9・理数 7・体育 8・音楽 8・美術 13・英語 7）。
科目表では `"school": "hsp"` で、科目選びでは「高校（専門）」にまとまります。

- 科目の名前と「扱う内容」は、`node tools/build-senmon-catalog.mjs --write` が、学習指導要領（平成 30 年告示）の本文（国立教育政策研究所の学習指導要領データベース）から取って、科目表に書きます。
  道具の中の表と本文とで、科目の名前や数が 1 つでも食いちがうと、書かずに止まります。
  体育・音楽・美術・英語は、本文の指導項目が短い（「独唱」「デッサン」など）ので、「扱う内容」は道具の中に書き起こしてあります。
- 職業に関する教科（農業・工業・商業・水産・家庭・看護・情報・福祉）は、「知識を学ぶためのもので、実習や資格の勉強の代わりにはならない」ことを、ホームと教科書に表示します。
  本文も、危険をともなう作業や介助は、手順ではなく「どこが危険で、どう防ぐか」を書かせ、点検でも確かめます（`VOCATIONAL_GUIDE`）。
  教科ごとの決まり（`SUBJECT_GUIDES`）では、資格や免許が必要な作業はそのことを書く、農薬や薬の量・殺菌の条件を言い切らない、
  看護では診療の補助にあたる技術（注射、与薬、吸引など）の手順を書かない、潜水のしかたを実行できる手順として書かない、などを定めています。
- 実技が中心の教科（体育・音楽・美術）は、運動・演奏・制作そのものは教えられないので、知識・理論・歴史・鑑賞と、練習や制作の考え方を扱います。
  ホームと教科書には「体を動かすこと・演奏・制作そのものは、このアプリでは学べません」と表示します。
- 学校では実習や課題研究として行う科目（課題研究、総合実習、実習、総合実践、総合調理実習、看護臨地実習、情報実習、介護総合演習、介護実習、スポーツ総合演習。科目表で `"practice": true`）は、進め方・記録・安全だけを扱う、短い科目にしています。
- 書き方の指示は、科目ごとに `"guide"` で選べます（例: 理数数学は `math`、福祉情報は `welfare+information`、水産の食品製造は `fishery+food`）。
- 専門教科の授業は、その分野の専門家が確かめたものではありません。法令・制度・基準の数値、医療や衛生、安全に関わる内容は、公開する前に専門家の確認が必要です。

新しい教科を足したときは、`node scripts/try-course.mjs <科目の ID>` で、単元表と授業 1 回ぶんを試しに作って出来ばえを確かめられます（ふだんのデータには触れません）。
`<科目の ID>=<言葉>` と書くと、名前や内容にその言葉をふくむ授業を選んで作ります（例: `hsp-fukushi-seikatsu-shien=移乗`）。

作った授業を別の AI（codex など）に精査させる手順は、ひとつ上のフォルダの `codex精査ガイド.md` にあります
（機械的な検査は `npm run check-lessons`）。
授業の「点検済み」の記録にもれがあるときは、アプリを閉じてから `node scripts/repair-lesson-index.mjs --write` で補えます。

## 起動

```bash
npm start
```

ひとつ上のフォルダにある `学びアイを起動.cmd` をダブルクリックしても起動できます。
開発しながら動かすときは `npm run dev`（保存するたびに画面へ反映されます）。

AI の応答には、この PC にログイン済みの `claude` または `codex` のコマンドを使います。
どちらを使うか・モデル・思考量は、ホーム画面や各モードの画面で切り替えられます。

## 音声（マイクで入力、読み上げ）

**音声認識**（`src/main/speech.ts`）は、[whisper.cpp](https://github.com/ggml-org/whisper.cpp) をこの PC の中で動かします。声を外へ送りません。
大きなファイルなのでアプリには同梱せず、ホームの「音声入力 → 音声認識を準備する」を押したときに取り寄せます。

| 取り寄せるもの | 入手先 | 大きさ |
| --- | --- | --- |
| エンジン `whisper-bin-x64.zip`（b5454） | GitHub の ggml-org/whisper.cpp のリリース | 8.5MB |
| 音声モデル（高精度）`ggml-large-v3-turbo-q5_0.bin` | Hugging Face の ggerganov/whisper.cpp | 547MB |
| 音声モデル（軽量）`ggml-small-q5_1.bin` | 同上 | 181MB |

取り寄せたファイルは、控えてある SHA-256 と照合します。置き場は `%APPDATA%\学びアイ\speech\` です。
マイクのボタンは、チャット・ディベート・テストの記述・ノートのタイピング・英会話・漢字特訓にあります。
文字になった言葉は入力欄に入るだけで、送信はされません（送る前に確かめて直せます）。
英会話の発音の確認は、言うはずの英文と、聞き取られた英文を単語ごとに照らし合わせ、80% 以上伝われば合格とします（`src/shared/pronounce.ts`）。

**読み上げ**は、PC に入っている音声を使います。画面側の読み上げ（speechSynthesis）で英語の音声が見つからないときは、
Windows の従来の系統（SAPI）の英語の音声（Microsoft Zira など）で読み上げます（`src/main/tts.ts`）。
どちらにも無い場合は、Windows の「設定 → 時刻と言語 → 音声認識 → 音声の追加」で「英語（米国）」を追加します。

## 漢字のデータ

漢字特訓の書き順・読み・学年は、同梱の `resources/kanji/kanji.json.gz`（6,400 字あまり）を使います。
[KanjiVG](https://kanjivg.tagaini.net/)（CC BY-SA 3.0）と [KANJIDIC2](https://www.edrdg.org/wiki/index.php/KANJIDIC_Project)（CC BY-SA 4.0）から
`tools/build-kanji-data.mjs` で作ったもので、データ部分は CC BY-SA 4.0 です。**配布するときは `resources/kanji/NOTICE.md` を同梱してください**
（アプリの漢字特訓の画面にも、出どころを表示しています）。
書き順の判定（`src/renderer/src/lib/kanjiStroke.ts`）は、書いた線と手本の線の位置・向き・長さをくらべるもので、AI は使いません。
その漢字を使う言葉と例文は、AI が 10 字ぶんずつ用意してためます。

## 動作確認

```bash
npm run build
npm run smoke                 # 画面の確認だけ（AI は呼ばない）
npm run smoke -- --ai         # 評価・会話・テストなどで AI を実際に呼ぶ
npm run smoke -- --ai --codex # AI を codex に切り替えて確認
npm run smoke -- --generate   # 未作成の授業を AI に書かせる確認
npm run speech-check          # 音声認識を実物で確認（準備済みのとき。--install を付けると取り寄せから行う）
```

アプリを実際に起動して操作し、結果と画面の写真を `.smoke/` に書き出します。
ふだんのノートや設定には触れず、ふだん使っているアプリを開いたままでも実行できます。
ノートの表示は、アプリ内の画面写真に加えて、実際の画面を取りこんだ絵でも確かめます
（表示の段階で起きる不具合は、アプリ内の写真には写らないため）。
音声認識の確認は、マイクの代わりに、Windows の読み上げ音声で作った音声ファイルを使います（人の声も、本物のマイクも要りません）。

## 表示倍率

- **画面全体**: どの画面でも、Ctrl + ;（+ のキー）で大きく、Ctrl + - で小さく、Ctrl + 0 で 100% にもどせます（Ctrl + マウスのホイールでも変えられます）。
  倍率は画面（モード）ごとに別々で、100%〜400% の間です。設定の画面では、スライダーで変えられます。
  大きくして画面に入りきらなくなったときは、スクロールできます。
- **ノートのページだけ**: 右下のスライダー、または Ctrl + Shift + スペースを押しながらのドラッグ（右上へで拡大、左下へで縮小）で、100%〜400% の間で変えられます。
  大きく拡大したときは、描く画像が大きくなりすぎないよう、1 ページの横幅を 4096 画素までにおさえています。

仕組み: 表示倍率は、同じ置き場（セッション）のページすべてに効くので、画面（モード）ごとに置き場を分けています（`src/main/index.ts` の `partition`）。

## ノートのショートカット

割り当ては、設定の画面で変えられます（一覧と、はじめの割り当ては `src/shared/keys.ts`）。
キーは文字ではなく位置で覚えるので、日本語入力がオンのときでも働きます。

| キー | はたらき |
| --- | --- |
| Delete | 最後に触れたページの書きこみを、すべて消す（範囲を選んでいるときは、その範囲だけ） |
| ← ／ → | 前の見開き ／ 次の見開き |
| スペース + ドラッグ | ページをつかんで動かす（下の「位置をもどす」で元にもどる） |
| M | 選択の道具に切りかえる。四角か投げなわで範囲を囲み、Delete で消す、ドラッグで動かす |
| Ctrl + Shift + スペース + ドラッグ | ページを拡大・縮小する（右上へで拡大、左下へで縮小） |
| Ctrl + Z ／ Ctrl + Y | 元に戻す ／ やり直す |
| （割り当てなし） | ペン、消しゴム、手書き／タイピングの切りかえ。設定の画面で、好きなキーを割り当てられます |

## 評価の決まり

- 1 週間は月曜から日曜。週が終わると、その週の評価が確定します。
- 理解力・応用力・発想力は、その週に評価を受けたノートの平均。記憶力は、その週のテストの平均点。
- 継続力は、10 分以上学習した日が 5 日で 50 点、合計 300 分で 50 点（`report.ts` の `PERSISTENCE`）。
- 5 つの力（100 点満点）は、ディベートで勝つ、英会話で 1 回やりとりする、漢字を 1 字クリアする、言葉を 1 語クリアするたびに、
  「100 点までの残りの一定の割合」だけ上がります（`skills.ts` の `RATES`）。
- 好感度の仕組みは、追加の要望書①で廃止しました（`affinity.ts` に処理は残してあり、`ENABLED` で止めています）。

## 教材とキャラクターの追加

- **科目**: `resources/content/catalog.json` に 1 行足します（ID、学校、教科、学習範囲、授業数の目安）。
- **授業**: `resources/content/<科目>/` に `curriculum.json`（単元表）と `<授業 ID>.md` を置くと「用意済み」になり、
  AI が作ったものより優先されます。授業の ID は `<科目>-<単元の番号>-<授業の番号>` です。
- **図**: 本文のコードブロックで、数直線（```` ```numberline ````、JSON）、関数のグラフ（```` ```plot ````、JSON。式から描く）、
  そのほかの図（```` ```figure ````、SVG。使ってよい要素と属性だけが表示される）を描けます。
- **掛け合い**: 本文のコードブロック ```` ```talk ```` に、「話し手(表情): せりふ」を 1 行ずつ書くと、顔と吹き出しで表示されます（下の「掛け合い」を参照）。
- **キャラクター**: 元のキャラクターシート（三面図 + 表情 3 種）は、ひとつ上のフォルダ（女子生徒 s01〜s10）と、その中の `男子生徒/`（s11〜s20）、`先生/`（みのり先生。ID は `sensei`）にあります。
  追加の表情（眠そう・考え中・困り顔・驚き）は、`node tools/gen-expressions.mjs <シートのフォルダ> <番号に足す数>` で、codex の画像生成を使って作り、
  `assets-src/` に置きます。先生は出番が多いので、`node tools/gen-expressions.mjs --teacher <シートのファイル>` で 2 枚

  人物の設定は `resources/content/characters.json` です。名前・性格・口調は、アプリの画面からも書きかえられます。

## 掛け合い

授業の本文の中で、先生と同級生が短い会話をします。目的は、読みはじめのきっかけ作りと、まちがえやすい所の確認です。

```talk
sensei(point): 今日は、**簿記**の入り口です。
s03(thinking): 簿記って、おこづかい帳みたいなもの？
```

- **書式**（`src/shared/talk.ts`）: 1 行が 1 つのせりふで、「話し手(表情): せりふ」。話し手は登場人物の ID、表情は省けます（持っていない表情なら、ふだんの表情になります）。
  登場人物に無い名前（歴史上の人物など）を書くと、名前の 1 文字目の札で表示し、「想像して書いたせりふ」であることを下に添えます。
- **AI に足させる**（`src/main/library.ts` の `addTalk`、指示文は `src/main/ai/authoring.ts`）: できあがっている授業の本文を AI に読ませ、せりふだけを書かせて、決まった位置に差しこみます。
  本文そのものは書きかえません（掛け合いを取りのぞけば、元の本文にもどります）。
  - 導入: 「この授業のねらい」のあと、本文の最初の見出しの前。
  - つまずきの確認: 「確かめ問題」の前。同級生がまちがいや迷いを口にし、先生かもう 1 人が、本文の説明にそって正します。まちがえやすい点が無い授業には入りません。
- **決まり**: せりふに出す事実・数値・用語は、本文に書かれているものだけ。まちがいは、必ずあとのせりふで正す。人をからかう表現はしない。
  学校に通っていることを前提にした話題を中心にしない。出てくるのは先生と、単元ごとに決まる同級生 2 人（同じ単元では同じ顔ぶれ）。
  歴史（中学の歴史、小学 6 年の社会、歴史総合、日本史探究、世界史探究）と倫理では、導入に、本文に出てくる歴史上の人物（亡くなって 100 年以上たった人）を 1 人だけ登場させられます。
  道徳には足しません（読み物そのものが、考える材料のため）。同梱の（人が書いた）授業にも足しません。
- **使い方**: 教科書のいちばん下の「AI に掛け合いを足してもらう」で、その授業に足せます（「掛け合いを作り直す」で作り直し）。
  全部の授業にまとめて足すときは、教材づくりの「できあがった授業に、先生と同級生の『掛け合い』を足す」を選びます（はじめは選ばれていません）。
  授業をすべて作り終えたあと、科目の順に足していきます。授業 1 回につき AI を 1 回呼びます。
- **試す**: `node scripts/try-talk.mjs <授業の ID> …` で、ふだんのデータを書きかえずに、`.try/talk/` に試作できます。
  試作を見本としてふだんのデータに入れるのは `node scripts/install-samples.mjs talk`（`--remove` で取りのぞく。アプリを閉じてから実行します）。
- 掛け合いも AI が書いたもので、人の確認は経ていません。

## 動く図解

読む人がスライダーなどで条件を変えると、図と数値が計算しなおされる部品です（実験の動画の代わり。決まった動画より、自分で条件を変えて確かめられます）。

```sim
{"kind": "pendulum", "values": {"length": 50, "angle": 20, "mass": 50}, "task": "ふりこの長さを変えると、1 往復の時間はどうなるでしょうか。"}
```

- **図の中身は、アプリが式から描きます**（`src/renderer/src/components/SimViews.tsx`、計算は `src/shared/sims.ts`）。AI が描いた図ではないので、数値のまちがいが入りません。
  AI が決めるのは、「どの図解を、どの値から始め、何を確かめさせ、どの節に置くか」だけです。値は、決まった範囲の中に丸められます。
- **いまある図解（10 種類）**: 分数の大きさくらべ（`fraction`）、グラフを動かす（`graph`。式の係数 a・b・c・k・p・q をスライダーで変える）、確率の実験（`dice`）、
  単位円と三角比（`unitcircle`）、ふりこ（`pendulum`）、てこ（`lever`）、ばねののび（`spring`）、回路と電流・電圧（`circuit`）、凸レンズと像（`lens`）、月の満ち欠け（`moon`）。
  図解ごとに、合う教科と学校が決まっています（`SIMS` の `subjects`・`schools`）。いまは算数・数学・理科だけです。
- **足し方**: 新しい図解は、`sims.ts` の `SIMS` に、名前・説明（AI に渡す）・動かせる量を足し、`SimViews.tsx` に描き方を足します。
- **AI に選ばせる**（`library.ts` の `addSim`）: 授業の本文を読ませ、合う図解があれば 1 つ選ばせて、指定された節の終わりに差しこみます。
  合うものが無い授業（大半の授業）には足さず、「調べたが無かった」と記録して、調べ直しません。
- **使い方**: 教科書のいちばん下の「AI に動く図解を足してもらう」で、その授業に足せます。
  まとめて足すときは、教材づくりの「算数・数学・理科の授業に、合う『動く図解』があれば足す」を選びます（はじめは選ばれていません）。
- **試す**: `node scripts/try-sim.mjs <授業の ID> …`（`.try/sim/` に試作）。見本として入れるのは `node scripts/install-samples.mjs sim`。

## 挿絵と、歴史上の人物の絵

- **置き場所**: 画像は、利用者のデータ置き場の `media/` に置き、何の絵か・出どころを `media/media.json` に書きます（`src/main/media.ts`）。
  `pictures` が挿絵（本文の ```` ```picture ```` の `id` で引く）、`people` が人物の絵（掛け合いに出てくる名前で引く）です。
  `kind` は、`generated`（AI が描いたイメージ）か `public`（公開されている肖像画や写真。`credit` に出典を書く）。
- **表示**: 挿絵には説明と、「AI が描いたイメージです。実際とちがうところがあるかもしれません」（`generated`）または「出典: …」（`public`）を、かならず添えます。
  掛け合いに出てくる歴史上の人物は、絵があればその絵、無ければ名前の 1 文字目の札で表示します。
- **生成する**（`tools/gen-pictures.mjs`。codex の画像生成）:
  `--lessons <授業の ID> …` は、授業の本文を読ませて、絵にすると分かりやすい場面を 1 つ選ばせて描かせます（置き場所と説明も一緒に決めさせる）。
  `--people "<名前>=<時代や服装の手がかり>" …` は、人物のバストアップを描かせます。どちらも、先生のキャラクターシートを絵柄の見本として添えます。
  できた絵は `assets-src/media/` に置かれ、`node scripts/install-media.mjs` で大きさを整えてデータ置き場に入れます（`--remove` で取りのぞく）。
  `--courses <教科の ID> …` は教科まるごと、`--guests <教科の ID> …` は掛け合いに出てくる歴史上の人物をまとめて描かせます。
  できた絵は、もう一度 codex に見せて確かめ、問題があれば 2 回まで作り直します（問題が残ったものは入れません）。
  宗教の開祖や信仰の対象になっている人物（ブッダ、イエス、ムハンマドなど）は描かせません。
- **公開されている肖像画や写真（資料画像）** は、3 段階で入れます。
  1. `node tools/fetch-materials.mjs <教科の ID か授業の ID> …`: 授業ごとに添えたい資料を 0〜2 点決めさせ、ウィキペディア日本語版・ウィキデータから候補を集め、
     ウィキメディア・コモンズの権利の情報で絞って取り寄せます。使うのは、パブリックドメイン（理由が確かめられるもの）・CC0・CC BY だけです（SA・NC・ND は使いません）。
  2. `node tools/photo-layer.mjs` → `node tools/audit-materials.mjs`: 権利の二重確認。はじめの道具は、コモンズのページに付いている権利の表示を全部読み直して控えます
     （彫刻など立体物の写真には「物」と「写真」の 2 つの権利があり、物の保護期間が終わっていても、写真が CC BY-SA のことがあるため。そういうものは見送ります）。コモンズの表示は「その写真」についてのものなので、撮影者が手放しただけのものは、写っている物を codex に分類させ、
     建物・遺跡・風景／古い物／実用品／1975 年より前の記録写真だけを通します（近現代の創作物・硬貨・切手・説明パネル、屋外の近現代の像、作者が推定のものは見送り）。
     「作者の没後 ○ 年」だけが根拠なのに、1900 年以降の作品で作者の没年が記録に無いもの、根拠がその国だけの表示のものも見送ります。
     そのうち、人がコモンズの記載を読んで問題が無いと確かめたものは、`assets-src/media/public/confirmed.json`（コモンズの題 → 確かめた内容）に書くと通ります。
     人が目で見て外した画像は `assets-src/media/public/rejected.json`（コモンズの題 → 理由）に書くと、どの授業でも使われません。
  3. `node scripts/install-media.mjs --materials`: 点検を通ったものだけを入れます。画面には「出典: 作者／Wikimedia Commons（ライセンス）」と、もとのページを開くボタンが出ます。
  権利の記録（題・ページ・ライセンス・根拠・作者・点検の結果）は `assets-src/media/public/items/*.json` に残ります。
- **人の目で確かめる**: 生成した絵には、時代に合わない建物や道具などのまちがいが入ることがあります。
  `node tools/review-list.mjs scenes`（または `materials`）で、まだ見ていない画像の一覧（`.try/review/`）を作り、見終えたら `--mark` を付けて記録します。
  `node scripts/install-media.mjs --reviewed-only` は、こうして「見た」と記録したものだけを入れます。
- `install-media.mjs` の `--scenes`・`--materials` は授業の本文に挿絵の印を差しこむので、教材づくりが動いていないときに実行します。

## 授業の動画（試作）

授業 1 つを、3〜5 分の解説動画にする試作の機能です（`src/main/video.ts`・`src/shared/video.ts`・`src/renderer/src/views/Video.tsx`）。

- **台本**: 授業の本文を AI に読ませ、場面（題・板書・本文の図・動く図解・挿絵）と、せりふ（字幕と、読み上げ用の文）の並びを書かせます。
  画面はアプリが台本から描くので、AI が決めるのは「何を、どの順に、どの画面を見せながら話すか」だけです。決まりに合わない台本は、わけを伝えて 1 回だけ書き直させます。
- **声**: この PC で動いている読み上げソフト（AivisSpeech。VOICEVOX と同じ形の入り口。`http://127.0.0.1:10101`）で、せりふを 1 つずつ音声にします。
  いまは「まお」の声（先生は「おちつき」、同級生は「ふつー」）だけを使うので、動画に出る同級生は女子 1 人です。声の利用条件（ACML 1.0）は、営利・非営利とも利用でき、クレジットは任意です。
- **読みの点検**: 読み上げソフトは、ときどき漢字を読みまちがえます。声を作る前に、読み上げソフトが決めた読み（カタカナ）を AI に見せ、AI 自身の読みも書かせて機械的に突き合わせ、
  まちがいがあれば読み上げ用の文を書きかえます（記録は `videos/<授業>/reading-check-*.json`）。
- **再生**: 教科書の下の「この授業を動画で見る（試作）」から開きます（動画がある授業にだけ出ます）。場面ごとに飛べます。
- **書き出し**: 「動画ファイルに書き出す」で、再生している画面と音をそのまま録画します（動画の長さだけ時間がかかります）。ffmpeg があれば MP4（1920×1080 まで）に、無ければ WebM のままにします。
- **置き場所**: `data/videos/<授業>/`（`script.json`・`audio/*.wav`・`audio.json`・`video.mp4`）。
- **試す**: AivisSpeech を起動しておき、`npm run build && node scripts/try-video.mjs <授業の ID> [--redo] [--no-record] [--install]`。
  ふだんのデータの写し（`.try/video-data`）で動かし、場面ごとの画面の写真を `.try/video-shots/` に、台本の読みやすい形を `script.txt` に出します。

## 授業の掘り下げ（Codex に評価させて、書き直す）

授業を Codex（GPT 6.2 Sol）に評価させ、掘り下げて分量を増やした版に書き直させて、元の授業と置きかえる。

```
node --no-warnings tools/deepen-lessons.mjs --schools jhs,hs      # 中学校と高校（共通の教科）
node --no-warnings tools/deepen-lessons.mjs --schools es          # 小学校
node --no-warnings tools/deepen-lessons.mjs --schools hsp         # 高校（専門）
node --no-warnings tools/deepen-lessons.mjs --schools es --deep   # 小学校の「学び直し版」（<保存名>.deep.md。763 件）
node --no-warnings tools/deepen-lessons.mjs --status              # 進み具合と、置きかえなかった授業
node --no-warnings tools/deepen-lessons.mjs --apply-only          # 読み直しを通ったものを、置きかえるだけ
node --no-warnings tools/deepen-lessons.mjs --accept 保存名,…    # 保留（held）の授業を、指摘を確かめ直したうえで置きかえる（--accept-note "確かめた内容"）
```

- 1 つの授業は、評価（codex）→ 掘り下げ（codex）→ 機械の検査 → 読み直し（claude）→ 置きかえ、の順に進む。途中で止めても、もう一度実行すれば続きから進む。
- 評価と掘り下げは、**その学校段階の学習指導要領と検定教科書を物差し**にする。評価は「本物の誤り」（生徒がそのまま覚えると誤答になるもの）と「軽微な点」（学校段階としてふつうの簡略化、言い回しなど）に分け、掘り下げでは本物の誤りを先に直す。学校段階としてふつうの簡略化は、直さない。
- 読み直しは、別の AI（claude の sonnet）が元の授業と見くらべて行う。重い問題（本物の誤り・学校段階をこえる内容・欠落・壊れた書式。学年への合い方が 5 点中 2 点以下のものもふくむ）があれば codex に直させ（2 回まで）、それでも残るものは置きかえない（`--status` に held と出る）。
- **小学校は、言葉づかいも学校段階のうちとして扱う**（2026-11-20 から）。学年のまとまり（1・2 年、3・4 年、5・6 年）ごとに、次を変える。
  - 分量のねらい: 1・2 年は いまの 1.5 倍（1,500〜2,400 字）、3・4 年は 1.6 倍（2,100〜3,400 字）、5・6 年は 1.7 倍（2,300〜3,800 字）。確かめ問題は、1・2 年は 5〜6 問、ほかは 6〜8 問。
  - 書き方の指示: 漢字とひらがなの使い分け・言葉のやさしさ・文の短さは、いまの本文にそろえる。新しく使う漢字は、その学年までに習う漢字だけ（名前や大事な用語を漢字で書くときは、（ ）で読みを添える）。おとな向けの言い回しを使わない。**1・2 年は、本文を分かち書きにそろえる**（もとの授業は、分かち書きのものと、そうでないものが混ざっていた）。
  - 機械の検査: その学年でまだ習わない漢字（同梱の漢字のデータ `resources/kanji` の学年で判定）が、元の授業に無く、読みも添えずに、新しく使われている数を数える。1・2 年は 2 字、3・4 年は 4 字、5・6 年は 6 字をこえたら、codex に直させる。
  - 読み直しの指示も、学年のまとまりごと（まだ習わない漢字・むずかしい言葉・長い文が目立って増えていれば、「学校段階をこえる」として指摘する）。
  - 学年に合った書き方かを数字で見るには `node .try/es-trial-report.mjs --all`（分量、文の長さ、漢字の割合、習わない漢字の数）。
- **高校（専門）は、授業を書いたときの専門教科の決まりを、掘り下げにも入れてある**（2026-11-20 から。`hspRule`・`hspEvalRule` と、読み直しの「専門教科として見ること」）。科目を 3 つに分ける: 職業に関する科目（農業・工業・商業・水産・家庭・看護・情報・福祉）、実技が中心の科目（体育・音楽・美術）、理数・英語。
  - 職業に関する科目: 「実習や資格の勉強の代わりにはならない」。けがや事故、健康の被害につながる作業（機械、電気、薬品、農薬、火、刃物、介助、医療的ケア、与薬など）は、**手順・分量・濃度・設定値を書き足さず**、しくみ・観察のポイント・危険と防ぎ方・決まりの理由を足す。法律・制度・規格・基準値は、資料で確かめられたものだけを書き、古い内容は直す。例に使う会社名・人名は架空のもの。
  - 実技が中心の科目: 知識・理論・歴史・鑑賞と、練習や制作を組み立てる考え方を足す。奏法・技法・体の動かし方を「やり方」として細かく足さない。
  - 実習・課題研究の科目（科目表の `practice`。16 科目）: 計画・進め方・記録とふり返り・安全と倫理を足す。分量のねらいは 1.4 倍（1,800〜3,600 字）と短め。
  - 分量のねらい: 職業・実技の科目は 中学校と同じ（1.7 倍、2,800〜5,500 字）、理数・英語は 高校と同じ（1.7 倍、3,400〜7,000 字）。

## Claude の中で作った教材を、アプリに取りこむ（大事）

Claude のデスクトップアプリは、Windows の「アプリごとの入れもの」（MSIX）の中で動く。その中から動かした道具（授業の掘り下げ・翻訳・挿絵・注釈・記述と論述の問題づくりなど）が
`%APPDATA%\学びアイ\data` に書いたファイルは、Windows が自動で `%LOCALAPPDATA%\Packages\Claude_…\LocalCache\Roaming\学びアイ\data`（Claude 専用の写しの置き場）に回す。
Claude の中からは、本当の置き場と重ねて見えるので気づかないが、**ふだんのアプリ（学びアイを起動.cmd）と、自分で起動した Web 版のサーバーからは見えない**。

- 取りこむ: アプリを閉じてから、`学びアイ\教材を取りこむ.cmd` を開く（中身は `node --no-warnings tools/sync-data.mjs --apply`）。付けずに動かすと、くらべるだけ。
- 同じファイルが両方にあるときは、新しいほうを残す。上書きする前のファイルは `<データ置き場>\backup-before-sync\<日時>\` に残る。ノート・会話・成績・設定は、写さない。
- Claude の中から本当の置き場を見るには、`\\localhost\C$\Users\<名前>\AppData\Roaming\学びアイ\data` の道すじを使う（この道すじは、写しの置き場に回されない）。
- Claude に道具を動かしてもらったあとは、そのつど取りこむ。

## メモ・文字起こし・用語集・検索・年表・記述と論述（2026-11-20 に足したもの）

### メモと、手書きの文字起こし

- **メモ**（ホームの「学びの道具」→ メモ）は、授業と関係なく使えるノート。名前を付けて、いくつでも作れる。先生の評価が無いこと以外は、ノートと同じ（ノートの種類 `kind: 'memo'`。画面は `views/Memo.tsx`、中身を書く画面はノートと同じ `views/Note.tsx`）。
- **文字起こし**（ノート・メモの上の「文字起こし」）は、手書きを AI に文字へ起こしてもらうだけの機能（評価はしない。好感度も変わらない）。
  AI に見せるのは、手書きの線だけを描いたページの画像（`renderPageImage(…, { inkOnly: true })`）。結果は、ページの `transcript` に入る。
  起こした文字は、タイピングした文字と同じように、検索・コピー・書き直しができる。「ページに入れる」で、タイピングの文字としてページに入り、
  「手書きを文字に置きかえる」で、手書きを消して文字だけにする（どちらも Ctrl + Z で元にもどせる）。
- どのページが「いまの手書きを、文字起こし済み」かは、`transcriptStamp`（線の数と、最後の線の ID）で見分ける。書き足す・消すと「まだ」にもどる。
- **まとめて文字起こし**は、メモの画面の下にある。すべてのメモとノートの、まだ起こしていないページを、4 ページずつ AI に渡す。画面を開いているあいだだけ進み、途中で止められる。

### ノートの消しゴムと、キー操作

- 消しゴムは、通ったところだけを消す（`note/render.ts` の `eraseStroke`）。大きさ（小・中・大・特大）と、消し方（部分・線ごと）を選べる。
  線は「点の並び」で持ち、太さは描くときに筆圧（マウスでは速さ）から決めているので、途中で切ると、残った部分の太さが変わって見える。
  そこで、切る前に「太さを決めた後の点」に直し（`baked: true`）、その点と太さのまま描く。
- 紙に触れたときに、入力の位置を紙へ移す（`PageSurface` の `onPointerDown`）。書くために「既定の動き」を止めているので、そのままだと、
  入力の位置が題名の欄や、Web 版ではとなりの画面に残り、書いた直後にショートカットキーが効かなかった。

### 画面の固定

- **Web 版**: タブのピンを押すと、その画面を固定する。固定した画面は、ほかの画面を開いても閉じず、ほかの画面は反対側に開く。「左右を入れかえる」で、側を変えられる。
- **パソコン版**: 画面の上の「固定」（または Ctrl + Alt + → ／ ← ／ ↓。設定で変えられる）で、そのウィンドウを画面の右半分・左半分に置く。
  固定中にほかの画面を開くと、そのウィンドウは反対側の半分に開く（`src/main/index.ts` の `pinned`）。

### 授業ごとの注釈（用語・ふりがな・関連する授業・年表）

教科書のふりがな・用語の解説・「この授業の前に」「関連する授業」、用語集、年表は、**授業ごとの注釈**から作る。

```
node --no-warnings tools/annotate-lessons.mjs --schools es,jhs,hs --model haiku --concurrency 40   # 授業ごとに、AI が注釈を作る（<データ置き場>/annot/<保存名>.json）
node --no-warnings tools/check-readings.mjs                                                          # 読みを、別のモデル（sonnet）にまとめて点検させて直す
node --no-warnings tools/build-glossary.mjs                                                          # 索引を作る（AI は使わない）: _glossary.json・_links.json・_timeline.json
```

- 注釈の中身: `terms`（用語・読み・簡単な解説・くわしい解説・別の書き方）、`readings`（ふりがなを付ける言葉と読み）、
  `prerequisites`・`related`（前提・関連する学習内容を表す言葉）、`events`（歴史の科目だけ。年表のできごと）。
  指示文・返事の形・確かめは `src/shared/annotate.ts`（道具とアプリで共通）。
- **ふりがなを付けるのは、用語・固有名詞・読みまちがえやすい言葉・その学年より上で習う漢字の言葉だけ**（全部の漢字には付けない）。
  本文に「庄内平野（しょうないへいや）」のように書かれた読みも、ふりがなを出すときはルビにする。表示は `lib/annotateText.ts`（rehype の部品）。
  ふりがなと用語の目印は、段落ごとに、はじめの 1 回だけ付ける。教科書の上の「ふりがな」か、設定で、出す・出さないを切りかえる。
- **関連する授業**は、注釈の言葉（前提・関連）を、その言葉を用語として学ぶ授業に結びつけて決める（小・中・高をまたぐ。`tools/build-glossary.mjs`）。
- **年表**は、歴史の科目（中学 歴史、高校 歴史総合・日本史探究・世界史探究、小学 6 年 社会）の注釈のできごとを、同じものをまとめて年の順に並べたもの。
- 注釈が無い授業は、教科書の下の「AI に、用語の解説とふりがなを用意してもらう」で、その場で作れる（索引に入るのは、`build-glossary.mjs` を動かしたあと）。
- モデルは Haiku 5.5 で足りる（2026-11-20 の試し: 1 件あたり Haiku 約 0.0075 ドル、Sonnet 約 0.07 ドル。解説の質の差は小さい。読みのまちがいは Haiku に少しあるので、`check-readings.mjs` で直す）。
- 注釈・用語集・年表は、日本語の授業から作る。表示の言語が日本語でないときは、使わない。

### 赤シート・用語集・検索

- **赤シート**（教科書の上）: 太字の大事な言葉を赤くかくす。言葉を押すと、その言葉だけ見える。
- **用語集**: 読みの順に並べ、言葉・学校・教科・行（あ・か・さ…）でしぼりこむ。用語を選ぶと、くわしい解説と、その用語を学ぶ学年・授業が出る。
  教科書で用語を押すと簡単な解説が出て、「用語集を開く」で、その用語のページが開く。
- **検索**: 教科書・ノート・メモ・用語集から探す。探す範囲（どれを探すか、教科書はどの学校・どの科目か）を選べる。
  本文の空白は無視して探す（低学年向けの分かち書きの本文にも当たる）。Web 版では、教科書は付属のサーバー（`/api/search`）が探す。

### 記述・論述の練習と、テストの特化モード

- **記述・論述の練習**（ホームの「力だめしと成績」、または教科書の下）: 記述は 100 字ほど、論述は数百〜千字を、序論・本論・結論に分けて書く
  （字数の目安は、学校と学年で変わる。`src/shared/essay.ts` の `writingTargets`）。

- 問題をまとめて作る: `node --no-warnings tools/make-essays.mjs --schools jhs,hs`（`<データ置き場>/essay/<保存名>.json`）。無い授業は、練習の画面で、その場で作れる。
- **テストの特化モード**（テストの準備の「問題の形式」）: いろいろ・選択だけ・記述だけ・論述だけ。選んだ形式の問題しか出ない（`TestFormat`）。

## Web 版（PWA・試作）

Electron 版と同じ画面（`src/renderer`）と本体側（`src/main`）を、ブラウザだけで動く形にまとめたもの。Chromebook・iPad で、いまのモードと教材がどこまで動くかを確かめるための試作。

```
npm run web:build      # dist-web/ に作る（vite.web.config.ts）
npm run web            # 付属のサーバー。http://127.0.0.1:5273/ で開く
npm run web -- --lan   # 同じネットワークのタブレットなどからも開く（表示される、合言葉つきの URL で開く）
```

### しくみ

- **画面**: 親のページ（`src/web/shell.tsx`）が、各画面（教科書、ノートなど）を iframe として開く。Electron 版の「ウィンドウ」は「タブ」になり、広い画面では 2 つ（漢字特訓は 3 つ）を並べて表示する。各画面は、Electron 版と同じ preload（`src/preload/index.ts`）で `window.manabi` を用意する。
- **本体側**: `src/main` の部品（教材・ノート・テスト・特訓・成績など）を、書きかえずにワーカーの中で動かす（`src/web/backend/`）。Node と Electron の部品は、ブラウザ用の代わり（`src/web/shims/`）に差しかえる。
  - **ワーカーの入口（`src/web/backend/worker.ts`）には、import 文を書かない。中身は `core.ts` に置く。** Safari 26（iPhone・iPad）には、ワーカーの入口のファイルを、ワーカーの中のほかのファイルが読みこむと、入口がもう一度はじめから動く不具合がある（WebKit の不具合 324459）。入口に共通の部品があると、分けて読みこむファイルが入口を読みこむ形になり、メッセージの受け口が「起動していないほう」に入れかわって、画面が 1 つも開かなくなる。できあがりがこの形になっていないかは、`vite.web.config.ts` の `workerEntryGuard` が、作るたびに確かめる（なっていたら、作るのを止める）。
- **保存**: 利用者のデータ（ノート・会話・成績・設定）は、ブラウザの中（IndexedDB）だけに残る。サーバーには置かない。
- **教材**: 授業・単元表・訳・画像は、開いたものだけをサーバーから取り寄せる（`/res/` = 同梱の資料、`/data/` = データ置き場の lessons・curricula・i18n・media）。サービスワーカー（`src/web/public/sw.js`）は、文字のもの（授業・単元表・科目表）を「つながるときは新しいもの、つながらないときは前に取ったもの」で返し、画像と音は「前に取ったものをすぐ返して、裏で新しくする」。科目ごとに「同梱の資料があるか」を 1 つずつサーバーにたずねると、起動のたびに数百回の通信になるので、上のフォルダの中身に無いフォルダは、たずねない（`src/web/shims/fs.ts` の `listing`）。
- **AI のつなぎ方**（画面の右上のボタンで選ぶ。`src/web/ai/`）
  - 開発用: 付属のサーバーが、この PC の claude・codex のコマンドを動かす（自分のプランの使用量を使う）。
  - 自分の API キー: キーを端末の中だけに置き、ブラウザから直接 API を呼ぶ（Claude は公式 SDK、OpenAI は Responses API）。
  - 運営者の API キー: サーバーの環境変数（`ANTHROPIC_API_KEY`・`OPENAI_API_KEY`）のキーで呼ぶ。仕事ごとのモデルの割り当て（`src/web/ai/routing.ts`）と、利用者ごとの 1 日の上限（`MANABI_DAILY_CAP_USD`。既定 0.5 ドル）・全体の 1 日の上限（`MANABI_TOTAL_DAILY_CAP_USD`。既定 20 ドル）を、サーバーが決める。
  - Sign in with ChatGPT: 利用者の ChatGPT のプランの枠で OpenAI を呼ぶ。サインインは、OpenAI の決まりどおり `http://127.0.0.1:1455/auth/callback` で受け、トークンは `%APPDATA%\学びアイ\siwc\credentials.json` に置く（ブラウザには渡さない）。

### 確かめ方（Safari）

Windows には Safari が無いので、同じエンジン（WebKit）の試験用ブラウザで確かめる。`npx playwright-core install webkit` で入る WebKit を、`playwright-core` の `webkit.launch()` で動かす。新しい `playwright-core` の WebKit は、出荷されている Safari より先の版なので、**Safari 26 の不具合は、`playwright-core@1.55.0`（WebKit 26.0）でないと再現しない。** スマートフォンの画面幅（375px など）では起動はするが、画面の組み立ては、タブレットと PC の幅に合わせてある（ホームが横にはみ出す）。

### Web 版でまだ使えないもの

- 音声の文字起こし（Electron 版は、PC の中の whisper.cpp）。英会話は、文字を入力すれば使える。
- 授業の動画（PC の読み上げソフトに頼っている）と、動画ファイルをノートに貼る機能。
- 授業のまとめての作成（教材づくりの、裏で作りつづける部分）。1 件ずつの作成・掛け合い・訳は動く。

python tools/model-check/render-notes.py .try/model-check <手書きのあるノート.json>   # 見本の画像を作る
node --no-warnings tools/model-check.mjs                                              # 6 つのモデルで試す（結果は .try/model-check/results.json）

## 大学・大学院の授業（試作）

科目表の `"school"` に、`univ`（大学・学部）と `grad`（大学院・修士課程の講義科目）がある。教科（`subject`・`subjectLabel`）は、学科や研究科にあたる（科目選びでは、学科ごとにまとまる）。
いまあるのは、試作の 12 科目（`tools/univ-courses.json`）: 数学科（線形代数学、微分積分学）、情報工学科（アルゴリズムとデータ構造、オペレーティングシステム）、
経済学科（ミクロ経済学、マクロ経済学）、心理学科（心理学概論、心理学統計法）、法律学科（憲法、民法総則）、大学院（機械学習特論、上級ミクロ経済学）。

- **高校までとのちがい**: 大学には、学習指導要領のような全国共通の内容の決まりが無い。物差しは、日本学術会議の「分野別参照基準」と、広く使われている教科書の組み立て（`src/main/ai/authoring.ts` の `HIGHER_BASIS`）。
  授業 1 回は、講義 1 回（90 分）ぶんで、学部は 3,500〜5,000 字、大学院は 4,000〜6,000 字がねらい。15 回が半期 2 単位、30 回が通年 4 単位にあたる。
- **書き方の指示**: 分野ごとに `SUBJECT_GUIDES` の `umath`（数学）・`ucs`（情報）・`uecon`（経済）・`upsych`（心理）・`ulaw`（法学）・`gml`（機械学習）。科目表の `"guide"` で、`ucs+umath+gml` のように組み合わせる。
  共通の決まりとして、参考文献を挙げない（実在しない文献を作らないため）、人名・年・条文の番号・判例・統計の値は確かなものだけ書く、評価の定まっていない最新の研究は断定しない、を入れてある。
- **画面の注意書き**: 大学・大学院の科目を開くと、「試作であること、専門家の確認を受けていないこと、単位や資格の勉強の代わりにならないこと」を出す（`Course.higher`、`CoursePicker.tsx` の `FieldNote`）。
- 単元表と授業は、ほかの科目と同じく、アプリの中（教科書の画面のボタン、または「教材づくり」）で作れる。

### モデルごとの比べ方（`tools/univ-trial.mjs`）

```
node --no-warnings tools/univ-trial.mjs --catalog      # 試作の科目を、科目表に書きこむ
node --no-warnings tools/univ-trial.mjs --curricula    # 単元表を作る（Opus）
node --no-warnings tools/univ-trial.mjs --write        # 科目ごとに授業を 1 回ぶん選び、Fable・Opus・Sonnet・Haiku に書かせる
node --no-warnings tools/univ-trial.mjs --judge        # Codex に、だれが書いたかを伏せて評価させる（1 件ずつの評価と、4 つの版の順位づけ）
node --no-warnings tools/univ-trial.mjs --classify     # 評価で付いた「誤り」を、はっきりした誤り・厳密さの不足・書き方の問題に分けさせる
node --no-warnings tools/univ-trial.mjs --report       # 結果の表（<データ置き場>/univ-trial/results.json にも書く）
node --no-warnings tools/univ-trial.mjs --fix          # アプリに入れる版に「本物の誤り」の指摘があれば、書いたモデルに直させて、もう一度評価させる
node --no-warnings tools/univ-trial.mjs --install      # 順位がいちばんよい版を、アプリの授業として入れる（アプリが閉じているときだけ）
```

- 指示文は、アプリが授業を作るときのもの（`src/main/ai/authoring.ts`）をそのまま使う。AI は、この PC の claude・codex のコマンドで呼ぶ。
- 時間は、1 件を書き終えるまでの秒数。使う量は、コマンドが知らせてくるトークンの数と「API で同じことをしたときの料金」。
- 評価は、書いたのと別の系統の AI（Codex の GPT 6.2 Sol）にさせる。同じ系統の AI に評価させると、自分の書き方をひいきするおそれがあるため。
- 途中の記録は `<データ置き場>/univ-trial/`（`drafts/` に各モデルの本文、`judge/`・`rank/` に評価、`metrics.json` に時間と量）。

### 2026-11-19 の試しで分かったこと（12 科目から 1 回ずつ、4 モデル。思考量は medium）

- **どのモデルの授業にも、誤りの指摘が付いた。** Codex がきびしく読むと、1 件あたり 4.7〜6.4 個（うち「はっきりした誤り」は Fable 2.6・Opus 2.8・Sonnet 3.0・Haiku 4.0 個）。指摘が 1 つも無かったのは、12 件のうち線形代数の 1 件だけ。大学の授業は、書かせたままでは出せない。
- **順位は Fable > Opus > Sonnet > Haiku**（順位の平均 1.5・2.2・2.6・3.8）。ただし、誤りの数は上の 3 つでほぼ同じで、料金は Fable が Sonnet の約 4 倍、Opus が約 2 倍。
- **直しを 1 回させると、指摘は半分強に減る（11 件で 53 → 23 個）が、ゼロになったのは 1 件。** 読み直すたびに、新しい指摘が出る。
- **Fable は、出力が不安定だった。** 22 回の呼び出しのうち、2 回は本文が出ず（やり直した）、3 回は本文の前に印（`[Fable 5.2 here]`、`<reasoning_effort>10</reasoning_effort>`）や考えのメモが付いた。本文の前の前置きは、道具（`lessonBody`）とアプリ（`src/main/library.ts` の `dropPreface`）で外す。
- **`\tag` は表示できない。** 1 行に書いた `$$…$$` は、文の中の式として組まれるので、`\tag` があると式が出ない（Opus と Sonnet が使った）。指示文で禁じ、入れるときに `\qquad\cdots(1)` の形に書きかえる（`untag`）。
- 情報の授業は、コードと解説の食いちがいが多かった（Fable の版で、本文のコードを実際に動かすと、解答の説明とちがう結果になった）。コードを機械で動かして確かめる仕組みは、まだ無い。

## 参考書と問題集（試作・調査）

中学校と高校（専門をのぞく）の単元ごとに、参考書 2 種類と問題集を作れるかを調べるための道具。アプリには、まだ入れていない。
学習の流れは「① 教科書を読む → ② 分からなかったところを、講義系か網羅系の参考書で学ぶ → ③ 問題集と参考書で練習する」。

| 種類 | 役目 | 1 単元の分量（試作の実測） |
|---|---|---|
| 講義系の参考書 | つまずくところを選び、話して聞かせるように「なぜ」を説明する。後半で入試の問われ方につなげる | 約 10,000 字（3〜5 講 + 入試ではこう問われる + その先へ） |
| 網羅系の参考書 | 要点をもれなく整理し、問題の型を【基礎】【標準】【入試】【発展】の例題で示す。辞書のように引く | 約 11,000 字（例題 約 11 題） |
| 問題集 | 全問に解答と解説。基礎 10 問・標準 10 問・入試 8 問（最後の 1〜2 問は発展） | 28 問・約 19,000 字 |

```
node --no-warnings tools/book-trial.mjs --write               # Claude（既定は sonnet・思考量 medium）に書かせる
node --no-warnings tools/book-trial.mjs --judge               # codex に点検させる
node --no-warnings tools/book-trial.mjs --fix                 # 指摘を、書いたモデルに直させて、もう一度点検させる（--round 3 で 2 回めの直し、--round 4 で 3 回めの直し）
node --no-warnings tools/book-trial.mjs --classify            # 指摘を、重さで分けさせる（claude の opus）
node --no-warnings tools/book-trial.mjs --report              # 結果の表（<データ置き場>/book-trial/results.json）
node --no-warnings tools/book-trial.mjs --export              # 見本を読むページの中身を書く（--max-round 3 で、2 回直した版までの中から選ぶ）
npx vite build --config vite.books.config.ts                  # 見本を読むページ（ひとつ上のフォルダの「参考書と問題集の見本/index.html」）を作る

# 書くモデルを変えて比べる（どの命令にも、同じ --model と --tag を付ける。記録は <名前>@opus のように分かれる）
node --no-warnings tools/book-trial.mjs --write --model opus --tag opus
node --no-warnings tools/book-trial.mjs --export --model opus --tag opus     # 見本は data@opus.js に書かれ、見本のページで切りかえて読める
node .try/book-models.mjs --tags ,opus,fable --subjects                      # モデルごとの数を並べる（空の名前が Sonnet）
```

## 言語の切りかえ（日本語・英語）

設定の画面のいちばん上で、表示の言語を選べます。切りかえると、アプリを開き直します（文言は、アプリを開いた時点の言語で決まるためです）。
いま選べるのは日本語と英語です。言語を足すときの手順は、この節の最後にあります。

### しくみ

- **画面の文言**: コードの中の文言は日本語のまま `t('…')`（文字列）か `tx('…')`（文の中に値や部品がはさまるもの）で囲んであります（`src/shared/i18n.ts`、画面側は `src/renderer/src/lib/i18n.tsx`）。
  日本語以外のときは、辞書 `src/shared/i18n/<言語>.ts`（日本語の文 → 訳）を引いて置きかえます。文の中の値は `{0}`・`{1}`…で表し、訳では順番を入れかえられます。辞書に無い文は、日本語のまま出ます。
- **AI への指示文**: 登場人物との会話・テスト・ノートの評価・講評（`src/main/ai/prompts.ts`）は、日本語の指示文と英語の指示文の 2 通りを持ちます。
  日本語以外の言語は、英語の指示文を共通で使い、「学習者に向けて書く言語」だけを言語ごとに指定します（`src/main/ai/lang.ts`）。ディベート・特訓などの指示文は、画面の文言と同じ辞書に訳があります。
  1 回だけの問い合わせ（`ai/ask.ts`）は、日本語以外のとき、指示文の最後に学習者の言語を書きそえます。表情タグは `[表情:名前]` と `[expression:name]` のどちらも読みます。
- **教材**: 日本語の教材が原本で、ほかの言語は、原本を訳した「写し」です。原本は、どの言語のときも書きかえません。

| 教材 | 訳の置き場所 | 作る道具 |
|---|---|---|
| 授業の本文 | `data/i18n/<言語>/lessons/<保存名>.md`（同梱の授業は `resources/content/<科目>/<授業の ID>.<言語>.md`） | `node tools/translate-lessons.mjs` |
| 単元表 | `data/i18n/<言語>/curricula/<科目>.json`（同梱の科目は `curriculum.<言語>.json`） | `node tools/translate-data.mjs --curricula` |
| 科目表 | `resources/content/catalog.<言語>.json` | `node tools/translate-data.mjs --catalog` |
| 登場人物 | `resources/content/characters.<言語>.json` | `node tools/translate-data.mjs --characters` |
| 画像の説明 | `data/i18n/<言語>/media.json` | `node tools/translate-data.mjs --media` |
| 掛け合いに出る人物の名前 | `data/i18n/<言語>/people.json` | `node tools/translate-data.mjs --names`（AI は使わない） |

- **訳がまだ無い授業**: 日本語のまま表示し、「まだ訳されていません」と出します。その場で 1 件だけ訳すこともできます（`src/main/translate.ts`）。
- **日本語のときだけの操作**: 授業を作る・掛け合いや動く図解を足す・まとめて作る（教材づくり）は、日本語で表示しているときだけ行えます（原本を作る・書きかえる操作のため）。
- **特訓**: 語彙力特訓の言葉と漢字特訓の言葉は、意味の説明を表示の言語で書かせるので、言語ごとに別にためます（`data/vocab/<言語>/`、`data/kanji/words.<言語>.json`）。練習する言葉そのもの（日本語の言葉・漢字・英単語）は、どの言語のときも同じです。
- **登場人物の書きかえ**: 名前や話し方を利用者が書きかえたものは、書いたときの言語のものとして覚えます。

### 授業を訳す

```
node tools/translate-lessons.mjs [--lang en] [--only 保存名,…] [--only-file ファイル] [--courses 科目,…] [--first 学校,…] [--concurrency 20] [--stale] [--recheck] [--redo] [--dry]
node tools/translate-data.mjs --curricula --media      単元表と、画像の説明
node tools/translate-data.mjs --names --titles         人物の名前の表を作り直し、授業の題を単元表にそろえる（AI は使わない）
```

- 訳し方の決まり（AI への指示文と、訳の形の確かめ方）は `src/shared/translate.ts` にあります。
- **形の確認**: 訳のあと、見出し・ブロック（掛け合い・挿絵・図解・図）・表が元と同じ形か、数式の `$` が閉じているかを機械的に確かめ、ちがえば 2 回まで訳し直します。
  訳し直すときは、どこがちがったかを、元の授業の形（見出しの並びなど）といっしょに AI に伝えます（`retryHint`）。
  挿絵や図解の ID・数値、掛け合いの話し手と表情は、訳がどう書いてあっても元のものにもどします。図の文字がはみ出しそうなときは、文字を小さくします。
- **教科ごとの訳し方**: 国語と書道は、学ぶ対象の日本語（例文・漢字・古文）を残して、説明を訳します。英語は、英文を残して、説明を訳します。
  英語の授業かどうかは、教科（`subject` が `english`）のほか、科目の手引き（`catalog.json` の `guide`）に `english` が入っているかでも決めます（「工業技術英語」のように、教科は工業でも英語を教える科目があるためです）。
  それ以外の教科では、日本語にしか当てはまらない説明（分数の読み順、音名のハニホヘト、選択肢のア・イ）を、その言語に合う形に直させます。
  ふつうの教科でも、日本語の言い回しそのものを扱う授業（敬語の使い方、日本の音階の名前など）は、日本語を残すのが正しい訳です。「日本語が残っている」で 2 回続けて落ちた授業は、確かめをゆるくして通し、記録（`lessons-index.json`）に `lenient` と書きます。
- **使用量**: claude が知らせてくる使用割合が、5 時間あたり 85%・週あたり 86% を超えたら休みます（`--five`・`--week` で変えられます）。休んでいるあいだは、1 時間ごと（回復の時刻が先に来れば、その時刻）に 1 件だけ訳して、回復していれば続けます（上限が、決まった時刻より前にもどされることがあるためです。見はりの部品は `tools/lib/claude.mjs`）。
  「上限が近い」という警告（allowed_warning）だけでは休みません。`--week 1.01` のように 1 より大きくすると、割合では休まず、上限に達して使えなくなったときだけ休みます（30 分ごとに試して続けます）。
- **順番**: `--first jhs` のように学校（es・jhs・hs・hsp）を書くと、その学校の授業を先に訳します。
- **意味にかかわる確かめ**: 形のほかに、次のことも機械的に確かめます（抜き取りの読み直しで、まとまって見つかった型です）。
  (1) 数式の中に日本語が残っていないか（「利益 = 売上 − 費用」のような式や、円・個などの単位）。
  (2) プログラムや擬似コードの中に日本語が残っていないか（文字列・コメント・データ・「もし〜ならば」などの言葉）。
  (3) 英語の授業で、問題文に答えの英文が出ていないか（「次の日本語を英語にしましょう」の日本語を訳すと、答えがそのまま見えてしまうため。指示文では、「肉を食べないことを英語で言いましょう」のように、言う内容を間接的に伝えさせます）。
  答えの文そのもの（4 語までの短い文）か、答えの大部分がひと続きで出ていたら落とします。「8 時に学校へ行くことを英語で言いましょう」のように、語が重なるだけのものは通します。
  (4) 英語の授業の問題文に、読みも意味も付いていない日本語の文が残っていないか（「(Use interesting.)」「(Hint: …)」のような指示は、意味の説明には数えません）。
  (5) 国語の授業の掛け合いで、せりふが日本語のまま残っていないか（例として引いた言葉は、日本語のままでかまいません）。
  (6) 掛け合いで、呼びかける名前を言い直していないか（「Koki... no, Haruto.」「Good point, Hinata... I mean, good thinking!」のような、訳すときの迷い。元のせりふが本当に言い直しているときは通します）。訳者のメモ（「Note: in the original …」）や、ほかの言語の文字（ロシア語の語など）が混ざっていないか。
  数式の中の `%` に `\` が付いていないもの（式が組めなくなる）と、ローマ字に混ざった形の似たキリル文字は、自動で直します。
  人が読んで「このままでよい」と決めた授業は、記録（`lessons-index.json`）に `accepted` と理由を書いておくと、`--recheck` の対象から外れます。
- **確かめ方を足したあと**: `--recheck` を付けると、いまある訳を、いまの確かめ方でもう一度確かめて、通らないものだけを訳し直します（通らなかった理由を、最初から AI に伝えます）。`--recheck --dry` は、何件が通らないかを理由ごとに数えるだけで、AI は呼びません。
- **元の授業を変えたあと**: 掛け合いや挿絵を足した授業は、訳が古くなります。`--stale` を付けると、元が変わった授業だけを訳し直します。
- 訳せなかった授業は `data/i18n/<言語>/failed.json` に理由つきで残ります（もう一度実行すると、その授業だけをやり直します）。

### 訳を読み直す（意味の点検）

形の確認では、意味のずれは見つかりません。訳した授業を AI にもう一度読ませて、意味のずれ・抜け・訳したせいで成り立たなくなった問題を探せます。

```
node tools/review-translations.mjs [--lang en] [--per-school 75 | --all] [--only 保存名,…] [--courses 科目,…]   読み直す（訳は書きかえない）
node tools/review-translations.mjs --report                                                              これまでの結果のまとめだけを出す
node tools/apply-review.mjs [--severity 重い|all] [--skip 保存名#番号,…] [--dry]                           見つかった直しを訳に入れる（AI は使わない）
```

全部の授業について、読み直しから直しまでを通しで流すには、次の 1 つを実行します（途中で止めても、もう一度実行すれば続きから進みます）。

```
node tools/review-pipeline.mjs [--five 0.85] [--week 0.86] [--rounds 2] [--concurrency 12] [--older-than 時刻] [--kinds 種類,…] [--max-fixes 回数]
```

1. 全部の授業を読み直す（`review-translations.mjs --all --wait`）。
2. 重い問題が見つかった授業を、その指摘を添えて訳し直す（`translate-lessons.mjs --from-review`）。訳し直す前の訳は `data/i18n/<言語>/previous/` に取っておきます。
3. 訳し直した授業を読み直し、重い問題が増えていたら前の訳にもどす（`settle-review.mjs`。AI は使いません）。
4. 2 と 3 を、1 つの授業につき `--rounds` 回までくり返したあと、授業の題と人物の名前の表をそろえて、まとめを出す。

進み具合は `data/i18n/<言語>/pipeline.json`（どの段か）と `review-progress.json`（読み直しの件数）で分かります。軽い問題（言い回しなど）は直しません。
1 回の読み直しで、重い問題がすべて見つかるわけではありません。2026-11-18 に全部の授業を 2 回ずつ読ませたところ、2 回めでも、英語を教える教科で 704 件のうち 36 件（5.1%）、ほかの教科で 10,366 件のうち 86 件（0.8%）に、新しく重い問題が見つかりました（どちらも直してあります）。3 回めを読ませれば、さらに少しは見つかるはずです。
重い問題は英語を教える教科に集まります（1 回めで 15〜21%。ほかの教科は 2〜3%）。
もう一度はじめから読ませるとき（2 回めの読み直し）は、`--older-than` に「いまの時刻」を書いて、同じ道具を実行します。

```
node tools/review-pipeline.mjs --older-than 2026-11-18T07:16:05Z --max-fixes 4 [--kinds general,japanese]
```

- `--older-than` より前に読んだ授業を、訳が変わっていなくても読み直します。読み直した授業は時刻が新しくなるので、途中で止めても、同じ時刻を書いてもう一度実行すれば続きから進みます（`review-translations.mjs --redo` は、毎回はじめから読みます）。
- `--kinds` は、訳し方の種類（`general` ふつうの教科・`japanese` 国語・`english` 英語）でしぼります。`review-translations.mjs --courses 科目,…` なら、科目でしぼれます。
- `--max-fixes` は、1 つの授業を訳し直す回数の上限です。前の回ですでに訳し直した授業も直せるように、「前の回までの回数 + `--rounds`」にします（2 回めなら 4）。

重い問題の原因が日本語の原本にある授業は、訳し直しても直りません。記録（`lessons-index.json`）の `fixes` を大きな数にして `note` に理由を書いておくと、訳し直しの対象から外れます。

- 何も付けないと、学校ごとに 75 件ずつを決まった順で抜き取ります（全体の質を見積もるため）。`--all` は全部を読みます（使用量は、訳すときと同じくらいかかります）。
- 結果は `data/i18n/<言語>/review/<保存名>.json`、問題のあった授業のまとめは `review-summary.json`、訳に入れた直しの記録は `review-applied.json` です。
- 直しを入れるのは、直す場所が訳の中にちょうど 1 か所だけ見つかり、入れても形がくずれないものだけです。AI の指摘がまちがっていることもあるので、`--dry` で中身を読んでから入れ、入れたくないものは `--skip` で外します。

## iPhone の直し・Codex の検査・ChatGPT Sites の試験（2026-11-20 に足したもの）

### iPhone・タブレットから http で開くとき（大事）

同じネットワークの端末から `http://192.168.x.x:5273/` のように開いたページは、ブラウザから見ると「安全でないページ」です。
このとき `crypto.randomUUID` が使えず、書いた線が保存されずに消える・漢字ノートが開かない、という不具合になりました。

- 画面の側で ID を作るときは、かならず `src/renderer/src/lib/id.ts` の `newId()` を使います（`crypto.randomUUID()` を直接よばない）。
- この不具合は 127.0.0.1 では再現しません。確かめるときは、別の名前を 127.0.0.1 に向けて開きます（`node .try/web-phone3.mjs`。Chromium を `--host-resolver-rules=MAP manabi.example 127.0.0.1` で起動する）。
- 同じ理由で、http で開いた端末では、マイク（音声入力）と、オフライン用の保存（サービスワーカー）は動きません。https で配れば動きます。
- スマートフォンでメニューをかくすときは、帯を `display: none` にせず、高さを 0 にします（`phone.css`）。どの画面も「帯の段 + 中身の段」の格子なので、帯を無いものにすると、中身の段がつぶれます。

### 検査で見つかった誤りを直す（Claude）

```
node --no-warnings tools/fix-extras.mjs --count                  # 直すものがある授業の数だけ見る
node --no-warnings tools/fix-extras.mjs --sample 100             # 決まった 100 授業だけ、案を作る（試し）
node --no-warnings tools/fix-extras.mjs --concurrency 8          # 全部の授業の案を作る
node --no-warnings tools/fix-extras.mjs --page                   # 直す前と後を見くらべるページを書き出す（試しの 100 授業）
node --no-warnings tools/fix-extras.mjs --page --courses jhs2-math --page-file ../検査の結果/直し-中2数学.html   # 科目をえらんで見くらべる
node --no-warnings tools/fix-extras.mjs --report                 # まとめ・不採用の一覧・本文にも誤りがある授業の一覧を書き出す

node --no-warnings tools/fix-extras.mjs --apply                  # 案を、教材に入れる
node --no-warnings tools/fix-extras.mjs --held                   # 保留（機械の確かめで通らなかったもの）だけを、もう一度たずねて入れる
```

- 検査役（Codex）の指摘を、別の AI（claude。既定は sonnet・思考量 medium）が 1 件ずつ確かめ、「採用・一部採用・不採用」と理由を付けます。採用した指摘がある用語・問題だけを、直した形で返させます。授業の本文は直しません（本文にも同じ誤りがあるときは、印を付けて知らせます）。
- 直すのは「誤り」の指摘と、字数の目安から外れた解答例。軽い指摘は、直す用語・問題に付いているものだけ、参考として渡します。
- 返事は、作るときと同じ確かめ（`src/shared/annotate.ts`・`essay.ts`）と、字数・学年の漢字（小学校）・分かち書き（1・2 年）の確かめにかけます。通らなければ 1 回やり直させ、それでも通らないものは「保留」にして入れません。
- 案は `<データ置き場>/fix/lessons/<保存名>.json`（案を作るだけでは、教材は変わりません）。見くらべのページは `学びアイ/検査の結果/直しの試し.html`。
- `--apply` は、直す前のファイルを `学びアイ/保管/直す前の用語と問題/` に写してから、`annot`・`essay` に入れます。案を作ったあとで教材や指摘が変わった授業には入れません。入れたあとは `node tools/build-glossary.mjs` で索引を作り直し、アプリには「教材を取りこむ」で入れます。
- 入れ終えた授業は、Codex で検査し直す（`inspect-extras.mjs`）まで、案づくりの対象になりません（手もとの指摘は、直す前の教材へのものだからです。`--count` に「直しを入れ終えた授業 … 件」と出ます）。
- `--held` は、保留の用語・問題だけを、前回通らなかった点を添えてたずね直し、通ったものをすぐ教材に入れます（記録の保留も置きかえます）。
- 直す役の AI には、文を 1 行にして見せています（改行は空白 1 つ）。返ってきた文には、直す前の文をたよりに、段落の切れ目（改行）を機械的に戻します（`tools/lib/fix-breaks.mjs`。問い・解答例が対象）。文が大きく書きかわって場所が見つからないときは、1 段落のままになります。
- 全体の結果（2026-11-20、4,294 授業）: 誤りの指摘 14,609 件 → 採用 12,347・一部採用 1,485・不採用 777（5.3%）、字数の直し 1,456 件。直したのは 用語 6,811 個・問題 5,071 問（保留は、`--held` のやり直しで 15 → 0）。「授業の本文にも同じ誤りがある」と付いた授業 595 件。API 換算 約 277 ドル、同時 10 で約 2 時間 20 分。まとめは `学びアイ/検査の結果/`（直しのまとめ.md・不採用の一覧.md・本文にも誤りがある授業.md・保留の一覧.md）。
- 全体の直しのあと、直した授業の約 5%（216 授業）を写しの上で Codex に検査し直させた結果: 誤りの指摘が付く割合は、用語 22% → 10%、問題 43% → 20%。直したものに、もう一度 指摘が付いたのは 用語 14%・問題 23%（はじめの検査で指摘が無く、変えていないものは 8%・17%）。不採用にして変えなかった用語 23 個には、19 個で同じ向きの指摘がもう一度付きました（検査役と直す役の見方がちがう点）。検査し直しの手順は `.try/fix-recheck2-setup.mjs`（写しを作る）→ `MANABI_DATA_DIR=写し` で `inspect-extras.mjs --only …` → `.try/fix-recheck-compare.mjs`。
- 目安（2026-11-20 の試し 100 授業）: 1 授業 約 20 秒・API 換算 約 0.064 ドル。誤りの指摘 307 件のうち 採用 278・一部採用 22・不採用 7、字数の直し 38 件、保留 0。

- 対象は、用語集・記述論述の直し（`fix-extras.mjs`）で「授業の本文にも同じ誤りがある」と印の付いた指摘のある授業（595 件・指摘 約 1,010 件）。
- 直す役（claude。sonnet・思考量 medium）が、指摘ごとに本文を読んで「誤りがある／直さない／本文には無い」を判定し、誤りがあるときだけ「本文のそのままの文（old）→ 直した文（new）」を返します。全文は書き直させません（全文を書き直させると、指摘の無いところに新しい誤りが入るため）。
- 機械の確かめ: old が本文にちょうど 1 か所ある／1 行の中／題・見出し・図やプログラムのブロックの中でない／掛け合い（```talk）の「名前(表情):」をふくまない／長さが元に近い／太字（**）・数式（$）・表の区切り（|）の数／小学校は学年の漢字と分かち書き。通らなければ 1 回やり直させ、それでも通らないものは「保留」。
- Codex の確かめ（`--verify`）: 同じ授業の差しかえを 1 つのまとまりで見せ（一緒に本文に入るため）、差しかえごとに ok・wrong・unneeded を付けます。**ok だけが、教材に入れる候補**です。wrong は `--revise` で 1 回だけ直し直して、もう一度確かめます。

- 入れたあとの確かめは `node .try/body-apply-check.mjs <保管のフォルダ>`（本文が「元 ＋ 入れた差しかえ」と一字一句同じか、差しかえのある行のほかは変わっていないか、指紋が合っているか）。

### ファイルを置くだけのサイトへの書き出し（ChatGPT Sites の試験）

```
npm run web:build
node --no-warnings tools/export-site.mjs --courses jhs2-math,jhs2-english,jhs3-science,hs-nihonshi
node .try/static-server.mjs ../sites-trial/dist 5275     # 手もとで確かめる（サーバーの機能なし）
node .try/web-static.mjs
```

- `tools/export-site.mjs` は、Web 版（dist-web）と、選んだ科目の教材を `学びアイ/sites-trial/dist` に書き出します。科目表は選んだ科目だけにし、用語集・関連する授業・年表の索引は、その科目だけで作り直します。
- 学びアイのサーバー（web/server.mjs）が答えていたことは、前もってファイルにします: フォルダの中身は `_list.json`、教科書の検索は `data/search/<科目>.json`。Web 版の側は、サーバーが答えないときに、それを読みます（`src/web/shims/fs.ts` の fetchListing、`src/web/backend/handlers.ts` の searchStatic）。
- このサイトで動かないもの: この PC の claude / codex を使う AI、サーバー経由の Sign in with ChatGPT。AI は、設定で自分の API キーを入れる方式だけが使えます。
- ChatGPT Sites について分かったこと（2026-11-20）:
  - この PC の Codex のコマンド（codex exec）から、Sites の登録・版の保存・公開ができます（道具の名前は `mcp__codex_apps__sites_*`）。新しいサイトは「所有者だけ」が見られる状態で始まります。
  - 載せる形は、静的（`.openai/hosting.json` の `static.directory`）か、Worker（`dist/server/index.js`。Cloudflare Workers）。静的なサイトは、データベース（D1）・ファイル置き場（R2）・秘密の値を使えません。
  - Sign in with ChatGPT は、Sites では申請なしで組みこめます（`/signin-with-chatgpt` へのリンク。サーバーの側が、ヘッダーで利用者の ID・メール・名前を受け取る）。分かるのは「だれか」だけで、訪問者の ChatGPT のプランで AI を動かす方法は、Sites の説明にありません。サインインした人を使うには、Worker の形が要ります。
  - 13 歳未満（または、その国のデジタル同意年齢未満）の子どもを対象にしたサイトは、利用規約で禁じられています。試験では、中学 2 年より上の科目だけを載せました。

#### Sites に載せる（Codex にたのむ）

書き出したフォルダを Sites に載せる・更新するのは、Codex にたのみます（学びアイ/sites-trial/CODEX_BRIEF.md に、たのむ文と決まりがある）。

```
cd ../sites-trial
echo "このフォルダの CODEX_BRIEF.md を読んで、そのとおりに作業してください。" | codex exec --skip-git-repo-check --sandbox workspace-write -c sandbox_workspace_write.network_access=true -m gpt-6.2-sol -c model_reasoning_effort=medium -o codex-result.md -
```

2026-11-20 の試験（4 科目・授業 183 回・1,434 ファイル・90 MB）で、登録 → push → 版の保存 → 「所有者だけ」のままの公開まで通りました（公開は 45 秒）。この PC でつまずいた点は 4 つで、どれも CODEX_BRIEF.md に書いてあります。

- Codex は、安全のために別の Windows ユーザーでコマンドを動かす。人が作ったフォルダでは Git が「持ち主がちがう」と止まるので、Codex 自身に作業用のフォルダ（sites-trial/site/）を作らせる。
- そのユーザーでは、Git の通信（Schannel）が使えない。その場かぎりで OpenSSL に切りかえる。
- まとめファイルを作る tar は、Windows 標準のものを使わせる（Git 付属の tar は `C:\…` を読めない）。
- Sites のリポジトリは、1 回の push が 64 MiB まで。大きいときは、コミットを分けて送る。

分かった数字: まとめファイル 81 MiB・1,435 ファイルは受けつけられた（ファイルの数と大きさの上限は、まだ当たっていないので不明）。全部の教材（約 550 MB・約 4 万ファイル）を同じ形で載せられるかは、段階をふんで確かめる必要があります。

## 公開に向けた調整（2026-11-22 に足したもの）

### 利き手・ノート

- **利き手**（設定 → 利き手。はじめは右利き）: `Settings.handedness`（`right`・`left`）。教科書といっしょに開くノートと、ノートの道具の列が、利き手の側に出る。
- **教科書で授業を開くと、その授業のノートも開く**（`Textbook.tsx` → `api.view.open('note', { lessonId, beside })`）。ノートは利き手の側に固定し、教科書は反対側に並ぶ（`main/index.ts` の `pinBeside`、Web 版は `web/shell.tsx` の `openView`）。
  - いっしょに開くノートは 1 冊だけ。授業を移ると、前の授業のノートは閉じる（`companion`）。書きかけは、ノートからフォーカスが外れたときに保存してある。
  - 自動で開くノートは、手前（キーの入力先）にしない。スマートフォンと、2 つ並べられない広さのときは、開かない。
- **ノートは 1 ページずつ・幅いっぱい**（見開きはやめた）。道具の列は縦にして、利き手の側に置く（`styles.css` の「ノートは 1 ページずつ」の節。スマートフォンは上の 1 行のまま）。ページ送りは `‹ 前へ`・`n / 全体 ページ`・`次へ ›`。
- **ペンの速さ**: 線を 1 本書くたびに保存が走って、次の線の書きはじめを待たせていた。ペンや指が下りているあいだは保存を始めず、保存までの間を 1.5 秒にした（`Note.tsx` の `SAVE_DELAY`）。ノートの一覧は、ファイルの時刻が変わったノートだけ読み直す（`store.ts` の `summaryCache`）。
- **指のジェスチャー**（iPad・Chromebook）: 2 本指で軽くたたく = 元に戻す ／ 3 本指で軽くたたく = やり直す ／ 2 本指で動かす = ノートを動かす ／ 2 本指を開く・閉じる = 拡大・縮小（`Note.tsx` の「指のジェスチャー」）。実機での確かめが要る。

`src/shared/types.ts` の `HIDDEN_SCHOOLS`（`univ`・`grad`）。画面の学校の一覧と、科目表（`main/content.ts` の `loadCatalog`）から外す。空にすれば、また出る。教材と道具は、そのまま残してある。

### AI のつなぎ方

配る版で使えるのは、次のとおり。それ以外の方式（この PC の claude・codex のコマンド、運営者のキー）は、開発のときだけ出る。

| | 自分の API キー（own-key） | Sign in with ChatGPT（siwc） | この PC のコマンド（relay） |
| --- | --- | --- | --- |
| Windows 版（インストーラーで入れたもの） | ○ | ○ | 出さない |
| Windows 版（`npm run dev` など、開発のとき） | ○ | ○ | ○（はじめは、これ） |
| Web 版（`npm run web:build`） | ○ | 出さない | 出さない |
| Web 版（`MANABI_WEB_ROUTES=all` をつけて作ったもの） | ○ | ○ | ○ |

- Windows 版: 設定の画面の「AI のつなぎ方」（`components/AiLink.tsx`）。本体側は `src/main/ai/link.ts`（つなぎ方の管理）と `src/main/ai/siwc.ts`（Sign in with ChatGPT）。
  - `src/main/ai/claude.ts`・`codex.ts` は入口で、つなぎ方に合わせて、コマンド版（`claude-cli.ts`・`codex-cli.ts`）か、API 版（`src/web/ai/`。Web 版と同じもの）に振り分ける。
  - API キーは `data/ai-link.json`、サインインのトークンは `data/siwc.json` に、Windows の仕組み（safeStorage）で暗号化して置く。画面（レンダラー）には、入っているかどうかだけを渡す。
  - `MANABI_AI_PUBLIC=1` で開くと、開発中でも配る版の形になる（動作確認のテストが使う）。`MANABI_AI_CLI=1` で開くと、配る版でもコマンドの方式が出る。
- Sign in with ChatGPT は、OpenAI の側（設定の AI が Codex のとき）だけで使える。選ぶと、AI は Codex に切りかわる。13 歳以上が対象。

### 配る版では出さないもの（開発用の版だけに出るもの）

- 教材づくり（ホームの「教材づくり」と、その画面。設定の表示倍率の一覧の行も）
- 教科書の「掛け合い」「動く図解」を、AI に足させる・作り直させるボタン
- この PC の claude・codex のコマンドで AI を動かす方式

決め方は、Windows 版が `src/main/edition.ts` の `isDevEdition()`（パッケージしていないときが開発用。`MANABI_AI_PUBLIC=1` で、開発中でも配る版の形になる）、Web 版が作るときの `MANABI_WEB_ROUTES`（`all` で開発用）。画面には `api.authoring`（preload が、開くときに 1 回だけ受け取る）で伝える。

### 配るものを作る

- **先に「教材を取りこむ」を済ませる**。Claude の中で作った教材は、取りこむまで「本当の置き場」に無い。取りこまずに、ふつうのターミナルで書き出すと、古い教材が出ていく（2026-11-22 に、中 1 の国語と理科の単元表だけ古い版のまま Web 版に出て、授業が欠けて見えた）。`release:prepare` は、取りこんでいない教材があるとき・単元表にある授業の本文が欠けているときは、止まる。
- `npm run release:prepare`（`tools/prepare-release.mjs`）: Web 版を作り、公開する科目の教材を `release/site/dist/` に書き出し（`tools/export-site.mjs --courses public`）、`THIRD_PARTY_NOTICES.md` を作り直して（`tools/build-notices.mjs`）、中身を確かめる。
- `npm run dist`: インストーラーを `release/win/` に作る（electron-builder。設定は `package.json` の `build`）。教材は `release/site/dist/data/` を `content-pack` として入れる。
- インストーラーで入れたアプリは、はじめて開いたとき（と、教材の版が変わったとき）に、`content-pack` を利用者のデータの置き場へ写す（`src/main/pack.ts`）。パックにあるファイルは、置き場の同じ名前のファイルを置きかえる（教材の新しい版にする）。パックを作った時刻（`pack.json` の `builtAt`）よりあとに書きかえられたファイルだけは、さわらない。
  - **開発している PC にインストーラーを入れると、開発中のアプリと同じデータの置き場（`%APPDATA%\学びアイ`）を使う**ので、置き場の教材が、インストーラーの中の教材で置きかわる。
- 公開の手順は [PUBLISHING.md](PUBLISHING.md)。ライセンスは、自作の分が MIT（`LICENSE`）、他人の素材は元のライセンスのまま（`THIRD_PARTY_NOTICES.md`）。
